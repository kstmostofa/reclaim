Every suggestion comes from one of these rules. A rule looks only at a folder's name, where it is and the files beside it; once a folder matches, nothing inside it is listed again. `~` means your home folder.

## Build caches

Output your project's tooling recreates on the next build or dev-server start. That first build is slower.

| What | Matched when | Level |
| --- | --- | --- |
| Next.js build cache | `.next` beside a `package.json` | <Level of="safe" /> |
| Nuxt build cache | `.nuxt` beside a `package.json` | <Level of="safe" /> |
| SvelteKit build cache | `.svelte-kit` beside a `package.json` | <Level of="safe" /> |
| Turborepo cache | any `.turbo` folder | <Level of="safe" /> |
| Parcel cache | any `.parcel-cache` folder | <Level of="safe" /> |
| Dart tool cache | `.dart_tool` beside a `pubspec.yaml` | <Level of="safe" /> |
| Python bytecode cache | any `__pycache__` folder | <Level of="safe" /> |
| Rust build output | `target` beside a `Cargo.toml` | <Level of="safe" /> |
| Gradle project cache | `.gradle` beside a Gradle build or settings file | <Level of="safe" /> |
| Android build intermediates | `build/intermediates`; built APKs in `build/outputs` are kept | <Level of="safe" /> |
| Xcode DerivedData | each project folder in `~/Library/Developer/Xcode/DerivedData` | <Level of="safe" /> |

## Dependencies

Packages your project installed. Run the install command again before using the project.

| What | Matched when | To get it back | Level |
| --- | --- | --- | --- |
| Node packages | `node_modules` beside a `package.json` | `npm install`, `pnpm install` or `yarn` | <Level of="rebuild" /> |
| Composer packages | `vendor` beside a `composer.json` | `composer install` | <Level of="rebuild" /> |
| CocoaPods | `Pods` beside a `Podfile` | `pod install` | <Level of="rebuild" /> |
| Python virtual environment | `venv`, `.venv` or `env` containing `pyvenv.cfg` | `python -m venv`, then reinstall requirements | <Level of="rebuild" /> |

<Callout>Packages that tools installed for themselves are skipped: anything in a hidden folder in your home (such as `~/.vscode/extensions` or `~/.composer`), in `~/Library`, or in system and Homebrew locations. Deleting those would break the tool, and there is no project to reinstall into.</Callout>

## Package caches

Downloads shared by every project, kept so they need not be fetched again. Deleting them only costs a re-download the next time a project needs them.

| What | Location | Level |
| --- | --- | --- |
| npm cache | `~/.npm/_cacache` | <Level of="safe" /> |
| pnpm store | `~/Library/pnpm/store` | <Level of="safe" /> |
| Yarn cache | `~/Library/Caches/Yarn` | <Level of="safe" /> |
| pip cache | `~/Library/Caches/pip` | <Level of="safe" /> |
| Composer cache | `~/Library/Caches/composer`, `~/.composer/cache` | <Level of="safe" /> |
| Gradle caches and wrapper downloads | `~/.gradle/caches`, `~/.gradle/wrapper/dists` | <Level of="safe" /> |
| Homebrew downloads | `~/Library/Caches/Homebrew` | <Level of="safe" /> |
| CocoaPods cache | `~/Library/Caches/CocoaPods` | <Level of="safe" /> |
| Cargo downloads and sources | `~/.cargo/registry/cache`, `~/.cargo/registry/src` | <Level of="safe" /> |
| Go build cache | `~/Library/Caches/go-build` | <Level of="safe" /> |
| Dart and Flutter packages | `~/.pub-cache`; run `flutter pub get` afterwards | <Level of="rebuild" /> |
| Playwright browsers | `~/Library/Caches/ms-playwright`; run `npx playwright install` afterwards | <Level of="rebuild" /> |

## App caches and logs

| What | Location | Level |
| --- | --- | --- |
| App cache | each folder in `~/Library/Caches`. The app rebuilds it and may start slower once. | <Level of="safe" /> |
| Logs | each item in `~/Library/Logs`, including crash reports | <Level of="safe" /> |

If the app a cache belongs to is running, the item shows a warning. Quit the app first.

## Mobile tooling

| What | Matched when | After deleting | Level |
| --- | --- | --- | --- |
| Android emulator snapshots | `snapshots` inside an emulator folder | The emulator cold-boots once | <Level of="safe" /> |
| Android emulator user data | `userdata-qemu.img` in an emulator folder | The emulator starts as if factory reset | <Level of="personal" /> |
| iOS device support | each version in `~/Library/Developer/Xcode/iOS DeviceSupport` | Copied again when that device is connected | <Level of="rebuild" /> |
| Simulator caches | `~/Library/Developer/CoreSimulator/Caches` | Recreated when needed | <Level of="safe" /> |

## App leftovers

Folders in `~/Library/Containers` and `~/Library/Application Support` named after an app's identifier (such as `com.docker.docker`) when no installed app has that identifier. Apple's own folders are never included, and an extension's folder counts as its app's. <Level of="personal" />

## Trash and old downloads

| What | Matched when | Level |
| --- | --- | --- |
| In the Trash | each item in your Trash; deleting it is the same as emptying the Trash | <Level of="safe" /> |
| Old download | each item in `~/Downloads` not changed for 90 days (adjustable) | <Level of="personal" /> |

## Large files

Files of 500 MB or more (adjustable) that no rule above covers, outside apps and photo libraries. <Level of="personal" />

## Docker

From Docker's own disk-usage report, when an engine is running. See [Docker and OrbStack](/docs/docker).

## System junk

Most of these belong to root, so deleting them needs the [helper](/docs/system). Items macOS protects are skipped even then.

| What | Location | Level |
| --- | --- | --- |
| System cache | each folder in `/Library/Caches` | <Level of="safe" /> |
| System logs | each item in `/Library/Logs` and `/private/var/log` | <Level of="safe" /> |

## Never suggested or deleted

- Anything inside an app, framework, photo or music library, or other bundle.
- Folders you list under [Never scan these folders](/docs/settings#scanning).
- Your Music, TV and Photos libraries, which macOS protects with permissions of their own.
- Protected folders, which cannot be deleted as a whole from anywhere in the app. See the [FAQ](/docs/faq#protected-folders).
